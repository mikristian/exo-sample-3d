# Signed notch inventory trust boundary — 2026-10-23 14:00

Scope: independent adversarial verification of `src/core/approvedNotchInventory20261023.js`; this isolated experiment does not approve Gerber data, production cutting, graded physical marks, or any factory output.

The verifier rebuilds its manifest from the supplied garment, checks a signed canonical JSON identity containing revision, base size, ordered size list, piece IDs and authored notch IDs, and compares it with the approved copy. A changed revision, missing piece, missing/added notch ID, changed size list or base size, invalid approved record, or invalid signature blocks the result. An attacker can recalculate a SHA-256 self-hash, but cannot obtain a matching Ed25519 signature under an independently pinned approver key. All manufacturing flags remain false even when an identity match succeeds.

**Critical operational trust boundary:** The function accepts `sourceRevision` and `trustedPublicKey` as caller arguments. It cannot independently prove that the revision is a reviewed immutable source commit, that the supplied key belongs to an authorized approver, or that the baseline captured all intended notches before approval. An adversary who can substitute their own public key alongside their signed payload can get `signed_inventory_identity_match` for the same reconstructed garment. Callers must pin the authorized approver key independently of the garment, approval record and editable workspace, authenticate revision against independently controlled source evidence, and retain immutable approval provenance and key revocation procedures.

**Other limits:** The signed manifest captures notch **IDs**, not `edgeIndex`, `t`, mark type, coordinates, contour, allowance, piece geometry, notch count derived independently from external design records, or DXF marks for each graded size. Moving a notch to another station or changing its physical representation while retaining its ID is outside this verifier's detection scope. A project with zero authored notches is rejected outright; this is a deliberate blocking policy for this experiment, and zero-notch production designs would need a separately reviewed explicit policy, never silent acceptance. The API's approval is relative to the supplied key and does not certify an approver's real identity or manufacturing readiness.

Recommendation: keep this validator outside manufacturing certification until a release boundary supplies an independently attested immutable revision and pinned key, compares reviewed notch geometry and graded exports, and fails closed on empty or unexpectedly missing source inventory. Treat identity matching as one input into release QA rather than authority to cut.
